# Задание 2 — дизайн API для списка магазинов‑партнёров

## 1. Цель и контекст

Цель API — предоставить мобильному приложению список магазинов‑партнёров «Петрушки зелёной» для отображения на экране, с возможностью перейти по ссылке в магазин‑партнёр при клике на карточку.

### Допущения

- Мобильное приложение работает с бэкендом магазина по REST API.
- Магазины‑партнёры описываются на стороне бэкенда и могут включать название, короткое описание, картинку и ссылку для перехода.
- Часть партнёров может быть временно выключена из показа (например, завершена акция).

---

## 2. Эндпоинт для получения списка магазинов‑партнёров

### 2.1. Описание

- **Метод:** `GET`  
- **URL:** `/api/v1/partner-shops`  
- **Назначение:** вернуть список магазинов‑партнёров для вывода в мобильном приложении.

### 2.2. Параметры запроса

Поддерживаются следующие query‑параметры:

| Параметр     | Тип      | Обязательный | Описание                                                                 |
|--------------|----------|--------------|--------------------------------------------------------------------------|
| `limit`      | integer  | Нет          | Количество элементов на странице (по умолчанию 20).                      |
| `offset`     | integer  | Нет          | Смещение от начала списка для пагинации (по умолчанию 0).                |
| `locale`     | string   | Нет          | Код локали (например, `ru-RU`, `en-US`) для локализации.                 |
| `onlyActive` | boolean  | Нет          | Если `true`, API возвращает только активных партнёров (по умолчанию `true`).|

### Пример запроса

```http
GET /api/v1/partner-shops?limit=20&offset=0&locale=ru-RU&onlyActive=true HTTP/1.1
Host: api.petroushka-zelenaya.ru
Authorization: Bearer <token>
Accept: application/json
```

---

## 3. Структура ответа

### 3.1. Формат ответа

Ответ возвращается в формате JSON и содержит массив партнёров и блок метаданных.

```json
{
  "data": [
    {
      "id": "shop_001",
      "name": "Магазин «Фермерские продукты»",
      "subtitle": "Свежие овощи и фрукты от локальных фермеров",
      "imageUrl": "https://cdn.petroushka-zelenaya.ru/partners/shop_001.png",
      "externalUrl": "https://partner-farmer.ru/petroushka",
      "isActive": true,
      "priority": 10,
      "category": "food"
    },
    {
      "id": "shop_002",
      "name": "«Эко-товары рядом»",
      "subtitle": "Эко-бытовая химия и товары для дома",
      "imageUrl": "https://cdn.petroushka-zelenaya.ru/partners/shop_002.png",
      "externalUrl": "https://eco-shop.ru/petroushka",
      "isActive": true,
      "priority": 8,
      "category": "household"
    }
  ],
  "meta": {
    "total": 2,
    "limit": 20,
    "offset": 0
  }
}
```



### 3.2. Описание полей

**Для объекта партнёра:**

| Поле          | Тип     | Обязательный | Описание                                                                 |
|---------------|---------|--------------|--------------------------------------------------------------------------|
| `id`          | string  | Да           | Уникальный идентификатор магазина‑партнёра в системе.                    |
| `name`        | string  | Да           | Название магазина, отображается на карточке.                             |
| `subtitle`    | string  | Нет          | Краткое описание или слоган, отображается под названием.                 |
| `imageUrl`    | string  | Нет          | URL изображения (логотип/баннер) для карточки партнёра.                  |
| `externalUrl` | string  | Да           | Ссылка, по которой нужно перейти при нажатии на карточку.                |
| `isActive`    | boolean | Да           | Флаг активности магазина; неактивные могут не возвращаться при `onlyActive=true`.|
| `priority`    | integer | Нет          | Числовой приоритет для сортировки (чем больше значение, тем выше в списке).|
| `category`    | string  | Нет          | Тип магазина (еда, быт, аптека и т.д.), пригодится для фильтрации в будущем.|

**Блок `meta`:**

| Поле     | Тип     | Описание                                                |
|----------|---------|---------------------------------------------------------|
| `total`  | integer | Общее количество магазинов с учётом применённых фильтров.|
| `limit`  | integer | Размер запрошенной страницы.                            |
| `offset` | integer | Смещение от начала списка.                              |

---

## 4. Переход по ссылке в мобильном приложении

При нажатии на карточку магазина‑партнёра мобильное приложение должно открыть ссылку из поля `externalUrl`.

### Возможные варианты реализации

- Если `externalUrl` — обычный HTTPS‑адрес, приложение открывает его во встроенном браузере (WebView) или передаёт в системный браузер.
- Если используется deep link (например, `petroushka://partner-shop/001`), клиент может по схеме понять, что нужно открыть внутренний экран, а не внешний браузер.

Это даёт гибкость: бэкенд может менять поведение перехода, не меняя клиент, достаточно изменить значение `externalUrl`.

---

## 5. Возможные расширения API

- **Фильтрация по категории** (`category=food`) или по городу/региону (`cityId`, если партнёры доступны не везде).
- **Возврат отдельного поля `trackingId`** или utm‑меток для аналитики переходов.
- **Добавление поля `description`** с более развёрнутым текстом на отдельном экране партнёра в приложении.
