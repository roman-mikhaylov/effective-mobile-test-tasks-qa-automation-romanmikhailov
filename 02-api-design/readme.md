# Задание 2 — дизайн API для списка магазинов‑партнёров

Решение второго задания из теста Effective Mobile (позиция системного аналитика / QA Automation).

По условию нужно было:

- спроектировать API для мобильного приложения, которое запрашивает и отображает список магазинов‑партнёров «Петрушки зелёной»;
- описать структуру запросов и ответов, параметры фильтрации, сортировки и пагинации;
- учесть сценарии клика на карточку магазина для перехода по ссылке в магазин‑партнёр;
- определить коды ошибок, требования к производительности и безопасности.

Текст задания предоставлен компанией и целиком здесь не приводится, ниже — только краткое описание.

## Структура решения

- `02-api-design.md` — полное описание спроектированного API: эндпоинты, модель данных, коды ошибок, пагинация, фильтры, сортировка, безопасность и производительность.

## Подход к проектированию

При разработке API я исходил из следующих принципов:

- **REST-архитектура** — единый эндпоинт `GET /api/v1/partners` для получения списка магазинов с параметрами запроса для фильтрации, сортировки и пагинации.
- **Минимальность и расширяемость** — базовая модель данных содержит только критичные для мобильного приложения поля, но легко дополняется новыми атрибутами.
- **Понятные коды ошибок** — чёткие HTTP-статусы и детализированные сообщения об ошибках для упрощения отладки и поддержки.
- **Пагинация и производительность** — offset/limit пагинация с разумными лимитами по умолчанию для снижения нагрузки и улучшения UX.
- **Безопасность** — токен-авторизация, валидация входных параметров, rate limiting для защиты от злоупотреблений.

Решение можно использовать как основу для обсуждения с командой разработки и уточнения деталей с бизнесом.
